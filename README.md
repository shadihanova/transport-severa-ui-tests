
# 🚌 UI-тесты для портала "Транспорт Севера"

Этот репозиторий содержит набор автоматизированных E2E (end-to-end) тестов для веб-портала "Транспорт Севера". Тесты написаны с использованием [Playwright](https://playwright.dev/) на языке TypeScript.

---

## 🚀 Быстрый старт

### 1. Клонирование репозитория
```bash
git clone <URL вашего репозитория>
cd transport-severa-ui-tests
```

### 2. Установка зависимостей
Установите все необходимые пакеты, включая Playwright и его браузеры:
```bash
npm ci
```

### 3. Настройка окружения
Для запуска тестов необходимо создать файл `.env` в корне проекта на основе `.env.example`.

1. Скопируйте файл `.env.example` в `.env`:
   ```bash
   cp .env.example .env
   ```
2. Откройте файл `.env` и заполните его актуальными данными:
   ```dotenv
   # URL тестового стенда (используется как baseURL в Playwright)
   BASE_URL='https://pub-dev.transflow.ru/#/'

   # Данные для первого тестового пользователя
   USER1_LOGIN=your_user1_login
   USER1_PASSWORD=your_user1_password

   # Данные для второго тестового пользователя
   USER2_LOGIN=your_user2_login
   USER2_PASSWORD=your_user2_password

   # Доступ к Testy TMS (для синхронизации и репортера)
   TESTY_API_URL=https://testy.altech.local/api/v1/
   TESTY_USERNAME=your_tms_login
   TESTY_PASSWORD=your_tms_password
   TESTY_PROJECT_ID=2
   ```

## ⌨️ Скрипты и команды

В `package.json` преднастроены следующие скрипты:

### Базовый запуск тестов
Используется для локальной разработки и отладки. Статусы в Testy TMS отправляться не будут.
```bash
npm run test
```

### Запуск с отправкой результатов в TMS
Используется при прогоне регресса. Кастомный репортер (`tms-reporter.ts`) автоматически проставляет статусы (`Passed`, `Failed`, `Skipped`) и прикрепляет логи к тест-кейсам в Testy.
```bash
# Запуск всех тестов с отправкой статусов в тест-план №430
npx cross-env TESTY_PLAN_ID=430 npm run test:tms
```
*(При указании родительского тест-плана репортер автоматически соберет все вложенные дочерние планы).*

### Синхронизация тест-кейсов из TMS
Вытягивает актуальные тест-кейсы из Testy TMS и складывает их в папку `docs/` в виде Markdown файлов.
```bash
npm run tms-sync
```

### Линтинг и форматирование кода
Для поддержания единого стиля кода используются ESLint и Prettier:
```bash
# Проверка кода на ошибки (ESLint)
npm run lint

# Автоматическое форматирование кода (Prettier)
npm run format
```

### 🧪 Интерактивный UI-режим
Открывает специальный интерфейс Playwright для удобной отладки:
```bash
npx playwright test --ui
```

## 🏷 Система тегов и фильтрации

Тесты разделены на проекты (пользователей) с помощью тегов в названии теста. 

### Как ставить теги:
* **Гостевые тесты:** Ставите тег `@no-auth`. Запускаются в чистой сессии браузера.
  ```typescript
  test('Проверка карты [TESTY-102] @no-auth', async ({ page }) => { ... });
  ```
* **Обычные тесты с авторизацией:** Если тест должен пройти под `user1`, ставьте тег `@auth`.
  ```typescript
  test('Успешный выход из системы [TESTY-1139] @auth', async ({ page }) => { ... });
  ```
* **Редкие тесты для второго пользователя:** Если тест должен пройти **только** под `user2`, ставьте тег `@user2`.
  ```typescript
  test('Проверка доступа юзера 2 к чужим данным [TESTY-1150] @user2', async ({ page }) => { ... });
  ```
* **Тесты под ОБОИМИ пользователями:** Если тест должен выполниться под обоими пользователями (например, проверка, что избранные остановки одного пользователя не видны другому), ставьте оба тега: `@auth @user2`. В этом случае `chromium-user1` выполнит его из-за `@auth`, а `chromium-user2` — из-за `@user2`.

### Команды запуска по проектам:
```bash
# Запуск только публичных тестов (без авторизации)
npx playwright test --project=chromium-no-auth

# Запуск тестов от лица User 1 (все тесты, кроме @no-auth и @user2)
npx playwright test --project=chromium-user1

# Запуск тестов от лица User 2
npx playwright test --project=chromium-user2
```

## 📂 Структура проекта

* `tests/` — Основная директория с тестами и вспомогательными файлами.
  * `tests/tests/` — Файлы с тест-кейсами (`*.test.ts`).

* `playwright.config.ts` — Главный конфигурационный файл Playwright.
* `.github/workflows/` — Настройки для запуска тестов в CI/CD (GitHub Actions).

## 🔄 Интеграция с Testy TMS (Test-as-Code)

Проект полностью синхронизирован с TMS системой Testy. Мы храним тесты как код и автоматически отправляем результаты прогонов обратно в систему.

### 📤 Отправка результатов (Из Кода в TMS)
Для отправки результатов используется кастомный репортер. 
**Важно:** В названии каждого теста должен быть указан ID тест-кейса в формате `[TESTY-123]` или `[123]`. Репортер парсит этот ID, ищет его в указанном тест-плане (`TESTY_PLAN_ID`) и отправляет HTTP-запросом результат выполнения (статус, время выполнения).

### 📥 Импорт тестовых наборов в `docs/` (Из TMS в Код)
Скрипт `scripts/tms-sync.ts` рекурсивно вытягивает тест-кейсы из Testy TMS и раскладывает их в папке `docs/` в формате структурированных Markdown-файлов (`.md`). Файлы содержат YAML-заголовки с ID и тегами, а также разбитые по шагам сценарии и ожидаемые результаты — идеальный формат для передачи контекста LLM.

**Команды выгрузки (через npm или напрямую ts-node):**
```bash
# Обновить весь проект (ID проекта берется из .env, по умолчанию 2)
npm run tms-sync

# Обновить конкретный сьют (например, ID 173)
npx ts-node scripts/tms-sync.ts -s 173

# Вытянуть конкретный кейс (например, ID 562)
npx ts-node scripts/tms-sync.ts -c 562
```

**Рабочий флоу при разработке новой фичи:**
1. QA пишут новые шаги и тест-кейсы в Testy TMS.
2. Вы локально выполняете `npm run tms-sync`.
3. Полученные `.md` файлы скармливаются ИИ-ассистенту (например, Cursor или GitHub Copilot) для быстрой генерации локаторов или обновления `.test.ts` файла.
```
