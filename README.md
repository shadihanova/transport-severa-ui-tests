# UI-тесты для портала "Транспорт Севера"

Этот репозиторий содержит набор автоматизированных E2E (end-to-end) тестов для веб-портала "Транспорт Севера". Тесты написаны с использованием [Playwright](https://playwright.dev/) на языке TypeScript.

## 🚀 Быстрый старт

### 1. Клонирование репозитория

```bash
git clone <URL вашего репозитория>
cd transport-severa-ui-tests
```

### 2. Установка зависимостей

Установите все необходимые пакеты, включая Playwright и его браузеры.

```bash
npm ci
```

### 3. Настройка окружения

Для запуска тестов необходимо создать файл `.env` в корне проекта. Он будет содержать URL стенда и данные для авторизации.

1.  Скопируйте файл `.env.example` в `.env`:

    ```bash
    cp .env.example .env
    ```

2.  Откройте файл `.env` и заполните его актуальными данными:

    ```dotenv
    # URL тестового стенда
    BASE_URL=

    # Данные для первого тестового пользователя
    USER1_LOGIN=your_user1_login
    USER1_PASSWORD=your_user1_password

    # Данные для второго тестового пользователя
    USER2_LOGIN=your_user2_login
    USER2_PASSWORD=your_user2_password
    ```

## ⚙️ Запуск тестов

### Обычный запуск (без отправки в TMS)

Используется для локальной разработки и отладки. Статусы в Testy TMS отправляться не будут.

```bash
npm run test
```

### Запуск с отправкой результатов в TMS

Используется при прогоне регресса, когда нужно обновить статусы тест-кейсов в Testy TMS.

Для автоматической отправки результатов прогона в Testy TMS используется кастомный репортер. Он автоматически проставляет статусы (`Passed`, `Failed`, `Skipped`) и прикрепляет логи ошибок к тест-кейсам.

Для этого используется специальная команда `test:tms` и переменная `TESTY_PLAN_ID`.

**1. Правила оформления тестов**
В названии каждого теста должен быть указан ID тест-кейса в формате `[TESTY-123]` или `[123]`:

```typescript
test('Проверка отображения карты [TESTY-456]', async ({ page }) => {
  // ...
});
```

**2. Настройка `.env`**
Для работы репортера добавьте в `.env` переменные доступа к TMS:

```dotenv
TESTY_API_URL=https://your-tms-url.com
TESTY_USERNAME=your_tms_login
TESTY_PASSWORD=your_tms_password
TESTY_PROJECT_ID=2
```

**3. Запуск**

```bash
# Запуск всех тестов с отправкой статусов в тест-план №430
npx cross-env TESTY_PLAN_ID=430 npm run test:tms
```

_(При указании родительского тест-плана репортер автоматически соберет все вложенные дочерние планы)_.

### Тесты в интерактивном UI-режиме

Открывает специальный интерфейс Playwright для удобной отладки тестов.

```bash
npx playwright test --ui
```

### Запуск по проектам и тегам

Тесты разделены на проекты (пользователей) с помощью тегов в названии теста:

**Только публичные тесты (без авторизации):**
Тег `@no-auth`. Запускаются в чистой сессии браузера.

```bash
npx playwright test --project=chromium-no-auth
```

**Только тесты с авторизацией (от лица User 1):**
Запускает все тесты, кроме гостевых и тестов юзера 2.

```bash
npx playwright test --project=chromium-user1
```

**Тесты от лица User 2:**
Тег `@user2`. Запускаются только специфичные тесты для второго пользователя.
_Если нужно выполнить тест под обоими пользователями, добавьте в название оба тега: `@auth @user2`._

```bash
npx playwright test --project=chromium-user2
```

**Запуск тестов по конкретному тегу (во всех проектах сразу):**

```bash
npx playwright test --grep @no-auth
```

## 📊 Отчеты

После каждого прогона тестов в корне проекта создается папка `playwright-report`. Чтобы посмотреть детальный HTML-отчет, откройте файл `playwright-report/index.html` в браузере.

```bash
npx playwright show-report
```

## 📂 Структура проекта

- `tests/` — Основная директория с тестами и вспомогательными файлами.
- `tests/tests/` — Содержит файлы с тест-кейсами (`*.test.ts`).
- `tests/pages/` — Page Object классы для инкапсуляции логики взаимодействия со страницами.
- `tests/data/` — Хранилище тестовых данных (пользователи, константы).
- `setup/` — Содержит тесты для предварительной настройки, например, для авторизации и сохранения сессии.
- `playwright.config.ts` — Главный конфигурационный файл Playwright.
- `.github/workflows/` — Настройки для запуска тестов в CI/CD (GitHub Actions).

## Памятка для написания автотестов

### 1. Как и где ставить теги в тестах:

- **Гостевые тесты:** Ставите тег `@no-auth`.
  ```typescript
  test('Проверка карты @no-auth', async ({ page }) => { ... });
  ```
- **Обычные тесты с авторизацией:** Если тест должен пройти под `user1`, ставьте тег `@auth` (или никак не ставьте, так как `grepInvert` пропустит его в любом случае, если нет `@no-auth`). Но с тегом `@auth` понятнее.
  ```typescript
  test('Успешный выход из системы [TESTY-1139] @auth', async ({ page }) => { ... });
  ```
- **Редкие тесты для второго пользователя:** Если тест должен пройти **только** под `user2`, ставите тег `@user2`.
  ```typescript
  test('Проверка доступа юзера 2 к чужим данным [TESTY-1150] @user2', async ({ page }) => { ... });
  ```
- **Если тест должен выполниться под ОБОИМИ пользователями** (например, проверка, что избранные остановки одного пользователя не видны другому): ставите оба тега `@auth @user2`.
  В этом случае `chromium-user1` его выполнит (так как есть `@auth`), и `chromium-user2` его выполнит (так как есть `@user2`).
