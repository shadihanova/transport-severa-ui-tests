# TESTY-1132: 1. Валидация полей формы регистрации: Проверка обязательности полей и подсветок невалидных данных

## Описание

Проверка подсветки красной рамкой (появления класса ошибки) пустых и невалидных полей (короткое имя/фамилия, невалидный email, короткий пароль, несовпадение паролей) и блокировки отправки формы.

## Сценарий

### Шаг 1

- **Действие:** Оставить все поля формы пустыми и кликнуть на кнопку «Зарегистрироваться» Ожидаемый результат: Форма не отправляется. Появляется всплывающее сообщение об ошибке (например, "Проверьте правильность заполнения полей"). Поля "Имя", "Фамилия", "Почта", "Пароль", "Повторите пароль" подсвечиваются красными рамками (появляется контейнер с классом ошибки).

### Шаг 2

- **Действие:** Проверка поля "Имя": ввести невалидные значения (например, "А" (1 символ) и " " (пробел)) Ожидаемый результат: При вводе каждого значения поле "Имя" подсвечивается красной рамкой (появляется класс ошибки у группы поля). Примечание: при необходимости перевести фокус на другое поле, чтобы сработала валидация.

### Шаг 3

- **Действие:** Проверка поля "Фамилия": ввести невалидные значения (например, "А" (1 символ) и " " (пробел)) Ожидаемый результат: При вводе каждого значения поле "Фамилия" подсвечивается красной рамкой.

### Шаг 4

- **Действие:** Проверка поля "Email": ввести невалидные значения (например, " " (пробел), "test@ru", "test.ru") Ожидаемый результат: При вводе каждого значения поле "Email" подсвечивается красной рамкой.

### Шаг 5

- **Действие:** Проверка поля "Пароль": ввести невалидные значения (например, "1234" (4 символа), " " (пробел)) Ожидаемый результат: При вводе каждого значения поле "Пароль" подсвечивается красной рамкой.

### Шаг 6

- **Действие:** Проверка несовпадения паролей: ввести в поле "Пароль" валидное значение (например, "qwerty123"), а в поле "Повторите пароль" отличающееся значение (например, "qwerty999") Ожидаемый результат: Поле "Повторите пароль" подсвечивается красной рамкой (валидация не пройдена из-за несовпадения).

## Итоговый ожидаемый результат

Все невалидные поля подсвечиваются красными рамками, а отправка формы регистрации с ошибками блокируется системой на каждом шаге.

- **Действие:** Нажать кнопку «Войти»
- **Ожидаемый результат:** Окно входа не закрывается. Снова появляется красный flash-баннер "Ошибка входа. Неверный E-mail или пароль", после чего автоматически скрывается.

## Итоговый ожидаемый результат

Авторизация блокируется системой при вводе неверного пароля или несуществующего Email, выводится соответствующее сообщение об ошибке.

## Описание

Проверка сохранения авторизованной сессии в хранилище браузера (localStorage/cookies) при включенном чекбоксе «Оставаться в системе» и её восстановление после имитации закрытия вкладки браузера.

## Сценарий

### Шаг 1

- **Действие:** Открыть боковое меню, нажать кнопку «Вход» и заполнить форму валидными данными (User 1)
- **Ожидаемый результат:** Открывается модальное окно авторизации, поля заполнены.

### Шаг 2

- **Действие:** Установить галку в чекбокс «Оставаться в системе»
- **Ожидаемый результат:** Чекбокс переходит в активное (нажатое) состояние.

### Шаг 3

- **Действие:** Нажать кнопку «Войти»
- **Ожидаемый результат:** Происходит успешный вход в систему. В боковом меню отображается кнопка «Выход».

### Шаг 4

- **Действие:** Сымитировать закрытие браузера: извлечь текущее состояние хранилища (storageState) и открыть новую вкладку (новый контекст) с передачей этого состояния

- **Действие:** Открыть главную страницу приложения в новой вкладке и проверить состояние меню
- **Ожидаемый результат:** Страница успешно загружается. В боковом меню сохраняется состояние авторизованного пользователя: отображается кнопка «Выход» и кнопка профиля с Именем и Фамилией (User 1).

## Итоговый ожидаемый результат

Сессия успешно восстанавливается в новой вкладке браузера при условии, что был активирован чекбокс «Оставаться в системе».
